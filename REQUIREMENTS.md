# Функциональные требования
## Назначение системы
Система предназначена для проведения одиночных онлайн-соревнований
по спортивному программированию.

В предметной области выделяются следующий основные сущности:

Для служебных нужд используются следующие сущности:
- *Журнал аудита*
- *Роли пользователей*
- *Разрешения пользователей*
- *Сессии*

## Требования к системе аккаунтов
1. Пользователь для регистрации в системе должен предоставить
адрес электронной почты, уникальный логин, состоящий из цифр и
букв латинского алфавита, а также пароль, состоящий из символов с
кодами ASCII из диапазона `0x20-0x7E` (обе границы включены) длиной
от 8 до 72 символов.
2. Зарегистрированный пользователь для входа в систему предоставляет свой логин
и пароль. Пользователь может выполнять вход с нескольких устройств одновременно.
3. Пользователи могут обладать следующими ролями:
    3.1. *Администратор* - управляет системой, обладает полными правами доступа.
    <!-- 3.2. *Менеджер* - имеет право создавать проекты, задачи, категории задач, зависимости между задачами в своих проектах, изменять статус задач, редактировать допустимые статусы, и назначать персонал на проекты. -->
    3.2. *Менеджер* - имеет право создавать проекты, назначается администратором;
    3.3. *Руководитель проекта* - менеджер, который в рамках данного проекта имеет право назначать персонал проекта на задачи внутри проекта; создавать задачи, категории задач;
    участвовать в обсуждении.
    3.4. *Сотрудник* - имеет право изменять статус задач, на которые он назначен, а также
    просматривать задачи всех проектов, в которых участвует, и обсуждать их.
    3.5. *Наблюдатель проекта* - сотрудник, который может просматривать
    статус данного проекта и принимать участие в обсуждении, однако не может
    назначаться на задачи.
4. Неавторизованные пользователи не имеют доступа к системе.
5. Для восстановления забытого пароля пользователю отправляется сообщение на
электронную почту, содержащее ссылку для восстановления.

## Проекты
Проект является контейнером для планирования. Проект имеет название и
описание, а также дату начала и дедлайн.
Каждый проект содержит задачи и обладает перечнем назначенного персонала.

### Персонал
В выполнении проекта участвуют определенные сотрудники. Руководитель
проекта отвечает за назначение сотрудников и наблюдателей.
Сам руководитель назначается администратором из числа менеджеров.

### Задачи
Задачи представляют собой шаги, необходимые
для завершения проекта. Каждая задача обладает названием,
описанием, зависимостями, дедлайном, статусом исполнения и оценкой
необходимого времени.

На задачу можно назначается один из сотрудников, задействованных в проекте.

Дедлайн задачи не может быть установлен на время,
более позднее позднее, чем дедлайн проекта.
Если задача не будет завершена в момент наступления дедлайна,
руководитель проекта и назначенный на нее сотрудники получают
уведомление по электронной почте.

### Зависимости
Для каждой задачи можно определить список задач внутри того же проекта,
от которых она зависит. Пока зависимости данной задачи не будут завершены,
она не может быть начата.

Дедлайн задачи не может быть назначен позднее дедлайна зависимости.
В случае, если зависимость задачи не была выполнена в срок,
дедлайн данной задачи сдвигается на один рабочий день вперед за
каждый рабочий день просрочивания дедлайна зависимости.

### Обсуждение
Сотрудники, участвующие в проекте, могут обсуждать все
задачи данного проекта. Обсуждение привязано к задаче.
Каждое сообщение обсуждения обладает заголовком и телом.
Пользователь может опубликовать сообщение непосредственно
под задачей или в качестве ответа на другое сообщение.

Сообщения отображаются в порядке добавления или
в виде древовидной структуры (если в обсуждении
присутствует хотя бы одно сообщение, пользователь может
ответить на него).

### Категории
Задачи опционально объединяются в категории. Категория имеет название
и отображается в графическом интерфейсе определенным уникальным
цветом. Одной задаче можно назначить несколько категорий.

Категории служат для облегчения упорядочивания задач и
их фильтрации в интерфейсе пользователя.

#### Статус исполнения
Для проекта можно определить несколько статусов исполнения
задач. Статус имеет два флага:
1. Флаг *готовности* означает, что выполнение задачи завершено
и разрешает выполнение зависимых задач.
2. Флаг *ожидания* означает, что работа над задачей не началась.
Изменять статус исполнения могу сотрудники, назначенные на задачу.

Пока работа над задачей не началась или не завершилось
выполнение ее зависимостей, она должна иметь статус с флагом готовности.

## Требования к журналированию
Система должна осуществлять журналирование всех действий, приводящих
к изменению базы данный. Каждая запись журнала содержит следующие данные:
- Временная метка;
- Идентификатор пользователя, совершившего изменение;
- Имя таблицы;
- Идентификатор измененной сущности;
- Произведенное над сущностью действие.
